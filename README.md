# PharmaCheck AI

Сервис анализа потенциальных лекарственных взаимодействий с Telegram-интерфейсом и serverless-развёртыванием в Yandex Cloud. Пользователь отправляет пару препаратов — сервис собирает доказательства из официальных источников и возвращает структурированный результат с уровнем риска и ссылками на источники.

## Ключевое архитектурное решение

Медицинская логика отделена от генеративной модели: детерминированный Python-код собирает и оценивает доказательства, формирует допустимые уровни результата и отклоняет любой ответ LLM за их пределами. Модель интерпретирует упакованные доказательства — но не принимает критических решений и не имеет инструментов для самостоятельного поиска.

```text
Telegram → Cloudflare Worker (relay, allowlist методов)
→ Yandex API Gateway → Cloud Function (приватная, вызов от сервисного аккаунта)
→ нормализация веществ (RxNorm) → сбор доказательств
  (DailyMed / openFDA, RxClass, DDInter*)
→ детерминированная оценка → YandexGPT (JSON Schema, валидация Pydantic)
→ ответ пользователю
```

\* DDInter используется только в некоммерческом режиме (лицензия CC BY-NC-SA); коммерческая конфигурация блокирует загрузку этого источника на уровне кода.

## Безопасность и надёжность

- Передача секретов через Yandex Lockbox; секретные значения не включаются в репозиторий
- Telegram webhook проверяет `secret_token` через `hmac.compare_digest`; защита от повторов по `update_id` действует в памяти одного экземпляра
- Cloud Function приватная; принцип минимальных прав для сервисных аккаунтов; IAM-токен из контекста выполнения вместо статических ключей
- Ошибка любого обязательного источника → безопасный ответ «недостаточно данных», а не ложное «совместимо» (fail-closed)
- Ответ модели проверяется JSON Schema / Pydantic независимо от заявленного формата API
- Воспроизводимый deployment-пакет (фиксированные timestamps в ZIP, контрольные SHA-256)

## Тесты

Исходная версия: 365 автотестов (pytest). В публичной копии воспроизводятся 353 теста; 12 проверок требуют исключённых каталога, маппингов, DDInter или внутреннего STATUS.md. Проверки сохраняются и включаются при наличии соответствующих файлов. Контрольные сценарии YandexGPT по умолчанию не вызывают платный API:

```bash
python -m pip install -e '.[dev]'
python -m pytest
PYTHONPATH=src python scripts/run_yandex_prompt_eval.py   # офлайн-просмотр контрольных сценариев
```

## Структура

- `src/pharmacheck/evidence.py` — детерминированная сборка и оценка доказательств
- `src/pharmacheck/sources/` — адаптеры источников: RxNorm, DailyMed, openFDA (резерв), DDInter (некоммерческий)
- `src/pharmacheck/yandexgpt.py` — проверяемая интеграция Yandex AI Studio Responses API
- `src/pharmacheck/telegram_webhook.py` — безопасный контроллер Telegram webhook
- `src/pharmacheck/cloud_runtime.py` — композиция Yandex Cloud Function
- `scripts/` — сборка deployment ZIP, проверяемый импорт выгрузки ГРЛС, верификация маппингов через официальный RxNorm
- `docs/architecture.md` — поток данных и границы доверия
- `docs/yandex_platform_conventions.md` — соглашения по Yandex Cloud (runtime, IAM, Lockbox, таймауты, логирование)
- `prompts/system_prompt_v1.txt` — системный промпт

## Локальная проверка и развёртывание

Офлайн-тесты работают на синтетических и изолированных fixtures без облачных ключей. Для развёртывания отдельно подготовьте выгрузку ГРЛС, проверенные сопоставления действующих веществ и необходимые данные источников. Скрипты не восстанавливают исключённые авторские маппинги автоматически.

В `deploy/` и runtime-константах реальные адреса заменены на `YOUR_GATEWAY_ID`, `your-account` и `${FUNCTION_ID}` / `${GATEWAY_SERVICE_ACCOUNT_ID}`. Перед развёртыванием настройте собственные адреса и согласованные allowlist-константы в `cloud_runtime.py` и `sources/openfda.py`. Инфраструктурные файлы — шаблоны, не готовая конфигурация действующего сервиса.

`PYTHONPATH=src python scripts/project_check.py` запускает публичный quality gate; при наличии приватных STATUS/manifest дополнительно проверяет их.
